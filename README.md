# REEVITA Cosmetics — منصة التجارة الإلكترونية الفاخرة

متجر إلكتروني فاخر مصمم باللغة العربية أولاً (Arabic-first RTL) لعلامة **REEVITA** لمستحضرات العناية بالشعر والبشرة والجسم، مخصص للسوق المصري مع نموذج الدفع عند الاستلام (COD).

المشروع مبني بهندسة متكاملة تجمع بين واجهة **Next.js 16** الحديثة وبنية خلفية قوية على **Supabase** مع نمط تشغيل مزدوج (**Dual Mode**) يعمل فوراً للتجربة بدون إعدادات مسبقة، وينتقل تلقائياً للربط السحابي الكامل عند توفير مفاتيح البيئة.

---

## 🌟 أبرز مميزات النظام

- **تجربة مستخدم فاخرة (Luxury RTL Experience):**
  - تصميم عربي أنيق مبني على أحدث معايير التصميم بتدرجات البورغندي والعاج والذهب (`Burgundy` / `Ivory` / `Gold`).
  - خطوط طباعية مختارة بعناية تجمع بين العناوين الفاخرة والنصوص الانسيابية عالية الوضوح.
  - صور منتجات WebP فائقة الجودة محسوبة بـ Blur placeholders تم استخراجها وتجهيزها من صور المصنع والمنتجات الأصلية.

- **كتالوج المنتجات الحقيقي (14 منتج عبر 5 خطوط):**
  - **Body Lotion** (Sexy, Queen, Ruby Musk) — لوشن الجسم المرطب المعطر (250 مل).
  - **Body Butter** (Sexy, Queen, Ruby Musk) — زبدة الجسم للترطيب المكثف (200 جم).
  - **Body Splash** (Sexy, Queen, Ruby Musk) — معطر الجسم المنعش (250 مل).
  - **Hair Mist** (Sexy, Queen, Ruby Musk) — معطر ومغذي أطراف الشعر (125 مل).
  - **Natural Shampoo** (Aloe Vera & Argan, Blueberry Extract) — شامبو الشعر الطبيعي الخالي من السلفات (500 مل).

- **الدفع عند الاستلام والشحن لمحافظات مصر (COD & Shipping):**
  - يدعم جميع محافظات مصر الـ 27 مقسمة لمناطق لوجستية (القاهرة الكبرى، الإسكندرية، الدلتا، القناة، الصعيد، المحافظات الحدودية).
  - حساب حي وتلقائي لرسوم الشحن وحد الشحن المجاني في الواجهة ومطابق 100% لسيرفر Postgres لمنع التلاعب بالأسعار.
  - تحقق وتطبيع فوري لأرقام الهواتف المحمولة المصرية لكافة الشبكات (010, 011, 012, 015).

- **تتبع آمن للطلبات (Anti-IDOR Privacy):**
  - شاشة تتبع للعميل تشترط إدخال رقم الطلب (`RV-2026-XXXXX`) ورقم الموبايل المسجل معاً، مع حجب كامل للبيانات الشخصية كالعناوين والإيميل.
  - مسار حالات واضح وتفاعلي من الإنشاء إلى التسليم (`new → confirmed → packed → shipped → delivered`).

- **لوحة تحكم كاملة للإدارة (Admin Dashboard):**
  - إدارة الطلبات والفلترة بحسب الحالة، التاريخ، المحافظة، أو البحث السريع.
  - تفاصيل الطلب وتحديث الحالات وإدخال اسم شركة الشحن ورقم البوليصة (Tracking Number).
  - إدارة وتعديل كميات المخزون وتنبيهات المخزون المنخفض (Low Stock Alerts) مع تتبع تلقائي في سجل الرقابة (`audit_log`).
  - تعديل تسعير الشحن وحد الشحن المجاني للمحافظات المصرية.

- **النمط المزدوج (Dual Mode Architecture):**
  - **وضع العرض التجريبي (Demo Mode):** يعمل محلياً للتطوير بدون مفاتيح خارجية، مع إدارة السلة وإتمام الطلبات وتتبعها في بيانات تجريبية.
  - **وضع الربط السحابي (Supabase Mode):** بمجرد إضافة بيانات الربط في `.env.local`، يتحول المتجر تلقائياً لاستخدام Postgres، وRLS، وAuth، ودوال RPC المؤمّنة بالمعاملات المالية وقفل الصفوف (`FOR UPDATE`).

## 🛠️ البنية التقنية (Tech Stack)

| الطبقة | التقنية المستخدمة | الغرض |
|---|---|---|
| **Frontend Framework** | **Next.js 16.4 (Turbopack, App Router)** | أداء فائق مع صفحات Server-rendered ديناميكية ودعم React 19 |
| **Styling** | **Tailwind CSS 4 + PostCSS** | نظام تصميم فاخر مع فئات توكنات متناسقة وتحكم كامل بالاتجاه RTL |
| **Icons** | **Lucide React** | أيقونات عصرية خفيفة وسلسة |
| **Validation** | **Zod v4** | تحقق صارم من بيانات المدخلات والهواتف والمخططات |
| **Database & Auth** | **Supabase (PostgreSQL 15+)** | إدارة البيانات، المصادقة، والسياسات الأمنية RLS |
| **Images Pipeline** | **Python (Pillow) + WebP** | معالجة وضغط وتوليد الـ Placeholders لصور المنتجات |
| **Testing** | **Node.js Test Runner + PGLite** | اختبارات سريعة ومعزولة لقاعدة البيانات والـ RLS بدون سيرفر خارجي |

## 🚀 البدء والتشغيل (Getting Started)

### 1. المتطلبات الأساسية
- **Node.js** إصدار `>= 20.9.0` (موصى بـ Node 22 أو 24).
- **npm** مثبت تلقائياً مع Node.
- **Python 3** (اختياري، مطلوب فقط إذا أردت إعادة تشغيل سكربت معالجة الصور من ملفات خام جديدة).

### 2. التثبيت
```bash
# تثبيت الاعتماديات
npm install

# تثبيت اعتماديات اختبارات الباك إند
npm --prefix tests/backend install
```

### 3. إعداد متغيرات البيئة
انسخ ملف الإعدادات النموذجي:
```bash
cp .env.example .env.local
```
> [!NOTE]
> إذا تركت ملف `.env.local` فارغاً، سيعمل المتجر فوراً وبشكل كامل في **وضع العرض التجريبي (Demo Mode)**.

للربط مع مشروع Supabase حقيقي، املأ المتغيرات التالية في `.env.local`:
```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key-here
NEXT_PUBLIC_SITE_URL=http://localhost:3000
NEXT_PUBLIC_ENABLE_ONLINE_PAYMENTS=false
```

### إشعارات الطلبات المجانية عبر Telegram
لإرسال تنبيه إلى تطبيق Telegram عند إنشاء طلب جديد:
1. أنشئ بوتًا عبر `@BotFather`، ثم افتح محادثة البوت من حساب الإدارة واضغط **Start** وأرسل `/start`.
2. أضف `TELEGRAM_BOT_TOKEN` إلى `.env.local` محليًا (ولا تشاركه أو تضعه في الواجهة).
3. استخرج رقم المحادثة بأمان من الطرفية عبر `node --env-file=.env.local scripts/get-telegram-admin-chat-id.mjs`.
4. أضف `TELEGRAM_BOT_TOKEN` و`TELEGRAM_ADMIN_CHAT_ID` في Vercel → Project → Settings → Environment Variables لبيئة Production، ثم أعد النشر.

يرسل التنبيه رقم الطلب وإجماليه ورابط لوحة الإدارة. يجب أن يكون اتصال الإنترنت وإشعارات Telegram متاحين على الهاتف لوصول التنبيه.

### 4. تشغيل خادم التطوير
```bash
npm run dev
```
افتح المتصفح على: [http://localhost:3000](http://localhost:3000)

## 🛡️ معايير الأمان (Security & Compliance)

1. **حماية التزامن ومنع الـ Overselling:**
   - يتم حجز المخزون داخل Postgres بقفل الصفوف المباشر `SELECT ... FOR UPDATE` أثناء تنفيذ عملية `place_order`. في حال طلب عميلين لنفس القطعة الأخيرة في نفس اللحظة، ينجح الأول ويتم رفض الثاني برسالة واضحة دون أي بيع بالزيادة.

2. **حساب المبالغ الموثوق سيرفر-سايد:**
   - لا تعتمد قاعدة البيانات نهائياً على أي أسعار أو رسوم شحن مرسلة من العميل. كل عملية حساب تتم داخل إجراءات Postgres الموثقة.

3. **حماية الخصوصية في تتبع الطلبات (Anti-IDOR):**
   - دالة `track_order` تتطلب مطابقة رقم الطلب مع رقم الهاتف ولا تُظهر عنوان العميل التفصيلي أو بريده الإلكتروني.

4. **سياسات Row Level Security (RLS) بنسبة 100%:**
   - جميع الجداول الـ 15 مفعل عليها RLS إجبارياً (`FORCE ROW LEVEL SECURITY`).
   - لا يمكن للزائر أو العميل العادي قراءة مخزون المنتجات بالأرقام الصريحة، بل يتم كشف حالة التوفر العام فقط عبر `product_availability`.

5. **رؤوس الأمان (Content Security Policy):**
   - تطبيق CSP صارم يعتمد على الـ Nonce المشفر في كل استجابة عبر `proxy.ts`.
   - لأن الـ Proxy يضيف CSP nonce لكل استجابة، تُعامل صفحات التطبيق كـ Server-rendered ديناميكيًا في الإنتاج؛ لا يعتمد النشر الحالي على prerendering ثابت للصفحات.
